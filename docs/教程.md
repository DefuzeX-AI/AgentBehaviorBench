# AgentBench 教程

这份教程从最基础的启动方式开始，逐步介绍 AgentBench 的 CLI 和 Python 用法。

## CLI

### 1. 准备环境

先进入项目目录。虚拟环境已经激活时，直接使用 `python`：

```bash
cd /Users/anthonyyao/Desktop/wangsong_project/ABB/AgentBehaviorBench
```

可以用下面的指令确认当前使用的是哪个 Python：

```bash
which python
```

如果输出路径包含项目目录下的 `.venv/bin/python`，说明当前虚拟环境已经生效。

### 2. CLI 指令的基本格式

AgentBench 的 CLI 基本格式是：

```bash
python -m agentbench <command> [options]
```

| 部分 | 示例 | 含义 |
| --- | --- | --- |
| Python | `python` | 使用当前激活的 Python 环境 |
| `-m` | `-m agentbench` | 按 Python package 启动模块 |
| package | `agentbench` | 要启动的项目 package |
| command | `sdk`、`run`、`view` | 要执行的 CLI 命令 |
| options | `--help`、`--sdk kuma` | 传给命令的选项 |

`-m` 是 Python 的启动选项。`python -m agentbench` 会找到
`agentbench/__main__.py`，再由它启动 CLI。

### 2.1 先区分几个名字

在 AgentBench 中，`SDK` 有特定含义。它指负责生成测试、接收 Agent 输出并给出评估结果的评测 SDK，例如 KUMA。

被测对象不叫 SDK，而叫 `Agent` 或 `Candidate`。它是我们要运行和评估的 Agent 项目。

| 名称 | 中文理解 | 在 AgentBench 中的作用 |
| --- | --- | --- |
| `Agent` / `Candidate` | 被测 Agent | 接收 Input，产生 Output |
| `Framework Adapter` | 框架适配器 | 让 AgentBench 能调用 LangGraph 等框架 |
| `Evaluation SDK` / `Evaluator` | 评测 SDK / 评测器 | 生成 Case、管理 Judge、保存评测结果 |
| `Benchmark Runner` | Benchmark 执行器 | 编排 Agent 和评测 SDK 的执行顺序 |

别人可能会把自己使用的开发包叫 SDK，例如 OpenAI SDK 或某个 Agent SDK。那是 Agent 内部使用的 SDK，不等于 AgentBench 这里的 Evaluation SDK。

为了避免歧义，后续设计中可以把 CLI 的 `--sdk` 逐步改成更明确的 `--evaluator`，同时保留 `--sdk` 作为兼容写法。

### 3. 第一个 CLI 指令：查看 SDK

```bash
python -m agentbench sdk list
```

这条指令的组成如下：

| 参数 | 类型 | 含义 |
| --- | --- | --- |
| `sdk` | command | 进入 SDK 相关命令 |
| `list` | subcommand | 列出当前可用的 SDK |

它会显示内置 SDK 和已经安装的 SDK plugin，例如名称、来源、版本和 Python 对象位置。

这条指令只读取 SDK 信息，不会启动 benchmark、Docker 或 Judge，适合作为第一次运行的检查。

### 4. 查看帮助

查看所有一级命令：

```bash
python -m agentbench --help
```

查看 SDK 命令的帮助：

```bash
python -m agentbench sdk --help
```

查看某个具体命令的帮助：

```bash
python -m agentbench run --help
```

### 5. 常用命令

| 指令 | 用途 | 是否会执行 benchmark |
| --- | --- | --- |
| `python -m agentbench sdk list` | 列出可用 SDK | 否 |
| `python -m agentbench sdk show kuma` | 查看一个 SDK 的信息 | 否 |
| `python -m agentbench run` | 运行所有 ready Agent | 是 |
| `python -m agentbench certify AGENT_ID` | 认证一个 Agent | 是 |
| `python -m agentbench observe --list` | 列出可观察的 Agent | 否 |
| `python -m agentbench observe AGENT_ID` | 运行一次观察任务 | 是 |
| `python -m agentbench evaluate AGENT_ID` | 在容器中执行一次正式评估 | 是 |
| `python -m agentbench view PATH` | 打开已经保存的结果 | 否 |
| `python -m agentbench clean --yes` | 清理本地结果历史 | 不执行 benchmark，但会修改本地文件 |

### 6. 选择 SDK

`run` 和 `certify` 可以使用 `--sdk` 选择评估 SDK：

| 选项 | 示例 | 适用场景 |
| --- | --- | --- |
| 默认选择 | 不写 `--sdk` | 使用内置 KUMA container SDK |
| 内置 SDK | `--sdk kuma` | 明确选择 KUMA |
| 已安装 plugin | `--sdk acme` | 选择 PyPI package 注册的 SDK |
| 指定 distribution | `--sdk acme-sdk::acme` | 解决 SDK 名称冲突 |
| Python module | `--sdk python:examples.local_sdk` | 本地开发和调试 |
| SDK 配置 | `--sdk-options sdk-options.json` | 从 JSON 文件读取 SDK 选项 |

例如：

```bash
python -m agentbench run --sdk kuma
```

这里的 `run` 是要执行的命令，`--sdk kuma` 是传给 `run` 的选项。
