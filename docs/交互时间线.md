# 查看 Agent、LLM、工具与 SDK 的交互

运行时打开 CLI 打印的网址，选择左侧 Run，再点击 **交互时间线**。
也可以用 `python -m agentbench view results/observe/<run_id>/run.json` 打开历史记录。
网址加上 `#view=raw` 可以直接进入时间线。

## 列表怎么读

| 内容 | 含义 |
| --- | --- |
| 时间 / 相对开始 | 本地时区的时分秒、毫秒，以及距离最早记录的秒数；完整时间戳在详情中 |
| Chat · 聊天 | 一次 LLM 请求及响应；同一 `call_id` 的流式片段合并显示 |
| Tool call · 调用请求 | 模型返回的工具名称、调用 ID 和参数；不代表已经执行成功 |
| Tool · 工具执行 | 框架记录的工具开始、结束或错误，按 `span_id` 聚合 |
| HTTP · 网络 | 已声明的其他 HTTP 请求；名称或 URL 不用于推断它是不是 SDK |
| SDK · 评测服务 | 显式声明 `purpose = "evaluation"` 的网络路由，或 SDK 生命周期事件 |
| Case / Input / Output / Submission / Judge | 已保存的出题、输入、结果、提交和判分快照 |
| Callback · 框架回调 | 框架的事件与输入输出；可以通过「包括所有回调」显示 |

顶部快捷按钮可以只看聊天或工具。搜索覆盖记录中的完整正文和 JSON，
还可以按 Input、状态和时间范围筛选。底部支持每页 10/20/50/100 条及跳转页码。
实时检测发现更新时会提示「载入更新」，避免翻页或阅读时列表跳动。
「刷新」立即重新读取当前列表；「检测更新」控制轮询。

## 打开一次交互

| 详情页签 | 能回答的问题 |
| --- | --- |
| 交互内容 | Agent 发送了哪些消息？模型说了什么、请求了什么工具？工具输入输出是什么？ |
| 请求与响应 JSON | 转换前请求、实际发送请求、上游响应和客户端响应分别是什么？ |
| Case 数据传递 | 对应哪个 Case/Input？完整 Input 值在实际请求的哪个 JSON 路径出现？最后提交了什么？ |
| 框架回调 | callback 记录了什么输入输出？关联的原始回调事件是什么？ |
| 原始记录 | 该次交互的全部原始事件，包括每个 chunk 的序号、字节数与耗时 |

JSON 支持树形展开、字段或值搜索、原文与复制。较大的内容用完整文本显示，
不为适配页面而截断。OpenAI Chat/Responses、Anthropic、Gemini 常见消息结构
有独立协议解析；不能识别的结构保留 JSON，不套用某个 Agent 的格式。

## 关联证据与历史数据

网络记录的 `framework_span_id` 必须唯一对应某个 Input 目录的回调，
或请求内的 `input_id`（及存在时的 `case_id`）唯一匹配，才显示 Input 关联。
同一 Input 目录中的快照直接关联。仅时间接近、域名相同或工具名称相同不算证据。

「找到完整 Input 值」表示实际请求里的值完全相同，或文本包含完整原文，
页面列出对应 JSON 路径。找不到不等于没传：输入可能经过转换或只取了一部分。
工具调用请求与实际执行也不因名称相同而自动建立因果关系。

旧快照没有事件时间时，时间线使用并标注**文件更新时间**。
旧 HTTP 事件如果只有地址，显示**历史记录仅保存了地址**；无法恢复当时未采集的正文。
HTTP 或框架回调缺失时仍可能看到提交快照，这些来源分别展示。

## 新 Agent / SDK 如何接入

1. Agent 的拦截配置声明真实的模型协议、host/path 和工具路由。工具路由默认
   `purpose = "tool"`；评测服务路由显式声明 `purpose = "evaluation"`。
   网络采集保存请求/响应 `call_id`、时间、正文、状态和耗时；不按域名推断用途。
2. Agent 的框架适配器输出标准 `span_start` / `span_end` / `span_error`，
   工具开始记录 `kind = "tool"`、`span_id`、`name` 和 `input`。
   当前 httpx/requests 的关联头只发给已声明的拦截目标，由代理转发前删除。
   其他客户端需要自己的关联适配；没有 ID 时页面保留为未关联。
3. SDK 通过 `BenchmarkProgress.artifact_directory` 注册 Run 目录；在
   `evaluation/case.json`、`evaluation/inputs/0001/` 等目录写入标准快照。
   `input.json` 提供 `input_id`、`case_id`、`payload`，其余快照为
   `mapped-input.json`、`request.json`、`result.json`、`submission.json`。
4. 如需精确的生命周期时间，在 `evaluation/sdk.jsonl` 记录带 `timestamp`、
   `source: "sdk"`、`event`、`data` 的事件；`data.artifact` 相对于 `evaluation/`，
   例如 `inputs/0001/submission.json`。SDK 的私有调用保留在自己的 adapter 中。

上述索引位于 `agentbench/observe/interactions.py`，Python viewer 和 Vite 共用，
不导入 KUMA。前端协议解析位于 `web/src/interactions/protocols.js`。

修改前端后在 `web/` 执行 `npm install` 和 `npm run build`，重启 Python viewer。
本次还扩充了拦截器与 worker 的采集；默认内容指纹构建会在下一次运行选择新镜像。
若通过 `DEFUZEX_MODEL_INTERCEPTOR_IMAGE` 指定静态镜像，需要自行更新该镜像。
新 HTTP 采集保留经脱敏的完整 JSON/文本或二进制 base64，不采集请求头与 URL 查询参数。
